# Как развернуть свой инстанс

Пошаговая инструкция: от пустого места до работающего бота с Mini App. Всё делается в браузере
и в Telegram — компьютер, сервер и навыки программирования не нужны. Займёт 15–20 минут.

**Что получится.** Ваш собственный бот на платформе
[Telegram Serverless](https://core.telegram.org/bots/serverless): код, база и Mini App живут на
инфраструктуре Telegram, а обновления выкладывает GitHub Actions из вашей копии репозитория.
Данные хранятся в базе вашего бота и ни с каким другим инстансом не связаны.

## Сколько это стоит

Платных шагов в инструкции нет:

| Что | Стоимость |
|-----|-----------|
| Бот в Telegram | бесплатно |
| Telegram Serverless: код бота, база, хостинг Mini App | свой сервер и платная база не нужны; условия и лимиты платформы — в [её документации](https://core.telegram.org/bots/serverless) |
| GitHub: копия репозитория и GitHub Actions | бесплатно для публичных репозиториев |
| Telegram Premium | не нужен |

Домен, хостинг, банковская карта не понадобятся.

## Что нужно заранее

- аккаунт Telegram;
- аккаунт GitHub ([регистрация](https://github.com/signup));
- по желанию — второй аккаунт Telegram или знакомый, чтобы проверить работу бота.

---

## Шаг 1. Создайте бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Задайте имя и username бота (username должен заканчиваться на `bot`).

BotFather пришлёт токен бота. Для этой инструкции он не нужен — просто никому его не
показывайте.

## Шаг 2. Включите Business Mode

Без него бот не увидит сообщения в ваших личных чатах.

В @BotFather: `/mybots` → ваш бот → **Bot Settings** → **Business Mode** → включить.

## Шаг 3. Включите Serverless и возьмите CLI-токен

1. В @BotFather: ваш бот → **Serverless** → **Enable**.
2. Там же: **Serverless** → **CLI Access** → **Access token**. Скопируйте токен — он выглядит
   как `app<цифры>:<секрет>`.

> Этот токен даёт полный доступ к коду и базе вашего бота. Храните его только в секретах
> GitHub (шаг 5). Если токен куда-то утёк — перевыпустите его в том же меню.

Запомните часть токена до двоеточия, `app<цифры>`: адрес вашего Mini App будет
`https://app<цифры>.tgcloud.ai/`. Он понадобится в шаге 7.

## Шаг 4. Сделайте свою копию репозитория

1. Откройте страницу этого репозитория на GitHub и нажмите **Fork** → **Create fork**.
2. В своей копии откройте вкладку **Actions** и нажмите кнопку включения workflow
   (**I understand my workflows, go ahead and enable them**).

## Шаг 5. Сохраните токен в секретах

В своей копии репозитория: **Settings** → **Secrets and variables** → **Actions** → вкладка
**Secrets** → **New repository secret**.

- **Name:** `TGCLOUD_TOKEN`
- **Secret:** токен из шага 3

Нажмите **Add secret**. Содержимое секрета после сохранения не видно никому, включая вас.

## Шаг 6. Запустите деплой

1. Вкладка **Actions** → слева **Deploy to Telegram Serverless** → **Run workflow** → **Run
   workflow**.
2. Подождите 3–5 минут, пока запуск не станет зелёным. Откройте его и убедитесь, что задача
   `deploy` выполнена, а не пропущена.

Что происходит за это время:

- код проверяется линтером и тестами;
- модули бота и Mini App выкладываются на платформу;
- в базе создаются таблицы;
- вебхук бота настраивается под обработчики;
- в базу записывается адрес Mini App, кнопка меню бота направляется на него;
- самопроверка убеждается, что всё работает на живой платформе.

Дальше деплой запускается сам при каждом изменении ветки `main` вашей копии.

Если запуск красный — см. [Если что-то не так](#если-что-то-не-так).

## Шаг 7. Включите Mini App в профиле бота

В @BotFather: `/mybots` → ваш бот → **Bot Settings** → **Configure Mini App** → **Enable Mini
App** и укажите адрес `https://app<цифры>.tgcloud.ai/` из шага 3.

После этого в профиле бота появится кнопка «Открыть», а ссылки вида
`https://t.me/<ваш_бот>?startapp` начнут открывать приложение.

> Тот же адрес печатает деплой: Actions → последний запуск → шаг **tgcloud deploy** → строка
> `Static: https://app….tgcloud.ai/`.

## Шаг 8. Подключите бота к своему аккаунту

1. В Telegram: **Настройки → Аккаунт → Автоматизация чатов** (в старых версиях — **Telegram
   для бизнеса → Чат-боты**).
2. Введите username вашего бота и выберите, какие чаты ему видны.
3. Откройте чат с ботом и нажмите кнопку меню слева от поля ввода — запустится Mini App.
4. Пройдите короткую настройку. На втором шаге можно в один тап создать **группу-архив**: в
   неё бот будет складывать копии фото, видео, голосовых и документов, по теме на каждого
   собеседника. Группу можно пропустить и подключить позже в Настройках.

## Шаг 9. Проверьте

Попросите кого-нибудь (или напишите со второго аккаунта) отправить вам сообщение и удалить
его. Через несколько секунд бот пришлёт уведомление с текстом удалённого сообщения, а в Mini
App оно появится в ленте.

Команда `/help` в чате с ботом покажет, что ещё он умеет.

## Шаг 10 (по желанию). Назначьте себя оператором

Оператор — тот, кто держит инстанс. Ему приходят уведомления об ошибках, доступны команда
`/admin` и раздел «Оператор» в Настройках Mini App.

1. Отправьте своему боту команду `/id` — он ответит вашим числовым Telegram id.
2. В своей копии репозитория: **Settings** → **Secrets and variables** → **Actions** → вкладка
   **Variables** → **New repository variable**. **Name:** `OPERATOR_ID`, **Value:** число из
   ответа бота.
3. Запустите деплой ещё раз (шаг 6).

Оператор назначается, только если он ещё не задан. Сменить его позже можно командой из раздела
[Деплой с компьютера](#деплой-с-компьютера).

## Как обновляться

Когда в исходном репозитории появляются изменения, на странице вашей копии GitHub показывает
кнопку **Sync fork** → **Update branch**. После нажатия деплой запустится сам.

Безопасные изменения базы (новые таблицы, колонки, индексы) деплой применяет сам. Если
обновление требует удалить или изменить что-то в базе, в логе деплоя появится предупреждение —
такие изменения применяются вручную командой `npm run migrate` с компьютера.

## Настройки инстанса

В коде нет ничего, что привязано к конкретному боту. Всё, что отличает ваш инстанс, лежит в
настройках вашей копии репозитория (**Settings → Secrets and variables → Actions**):

| Где | Имя | Обязательно | Что это |
|-----|-----|-------------|---------|
| Secrets | `TGCLOUD_TOKEN` | да | CLI-токен из BotFather. По нему деплой узнаёт, в какого бота выкладывать |
| Variables | `OPERATOR_ID` | нет | Числовой Telegram id оператора |
| Variables | `APP_URL` | нет | Адрес Mini App. Обычно не нужна: деплой берёт адрес из начала токена |

## Деплой с компьютера

Подойдёт тем, кто не хочет пользоваться GitHub Actions. Нужны [Node.js](https://nodejs.org) 20
или новее и git.

```bash
git clone <адрес репозитория>
cd <папка репозитория>
npm ci
npx tgcloud login        # спросит CLI-токен из шага 3
npm run deploy           # сборка Mini App и выкладка
npm run migrate          # создать таблицы в базе
```

Затем один раз настройте инстанс:

```bash
npm run admin -- '{"setAppUrl": "https://app<цифры>.tgcloud.ai"}'   # адрес Mini App
npm run admin -- '{"setMenuButton": true}'                          # кнопка меню бота
npm run admin -- '{"setOperator": <ваш id>}'                        # по желанию
npm run admin -- '{"selftest": true}'                               # самопроверка
```

Остальные шаги (7–9) те же. Все команды оператора перечислены в начале файла
`tgcloud/lib/admin.js`; сводка по инстансу — `npm run admin -- '{}'`.

## Если что-то не так

**Во вкладке Actions нет «Deploy to Telegram Serverless» или кнопки Run workflow.**
Workflow в копии репозитория выключены по умолчанию — включите их (шаг 4).

**Запуск зелёный, но задача `deploy` помечена как пропущенная (skipped).**
Деплой не нашёл секрет `TGCLOUD_TOKEN` и ничего не выкладывал — в сводке запуска об этом есть
заметка. Создайте секрет именно на вкладке **Secrets** как *repository secret* (шаг 5) и
запустите деплой снова.

**Деплой падает на шаге «tgcloud deploy» с `Invalid token format` или ошибкой доступа.**
Секрет `TGCLOUD_TOKEN` скопирован не целиком. Он должен выглядеть как
`app<цифры>:<секрет>`, без пробелов и переносов. Создайте секрет заново (шаг 5).

**Деплой падает на шаге «tgcloud selftest».**
В логе шага есть строка `selftest FAIL: …` с причиной. Чаще всего у бота не включён Serverless
(шаг 3) или деплой запустили до его включения — включите и запустите деплой снова.

**Бот не реагирует на удаления и правки.**
Проверьте по порядку: включён ли Business Mode (шаг 2); подключён ли бот к вашему аккаунту и
виден ли ему нужный чат (шаг 8); включены ли уведомления в Настройках Mini App. Бот видит
сообщения только с момента подключения и только в личных чатах.

**Mini App говорит, что подключения нет, хотя бот добавлен.**
Событие о подключении Telegram присылает один раз. Выключите и снова включите бота в
«Автоматизации чатов».

**В чате с ботом нет кнопки меню.**
Деплой ставит её сам и пишет предупреждение, если не получилось. Вручную: @BotFather →
`/mybots` → ваш бот → **Bot Settings** → **Menu Button** → укажите адрес Mini App. Либо с
компьютера: `npm run admin -- '{"setMenuButton": {"force": true}}'`.

**Кнопка «Открыть» под уведомлением ведёт по ссылке, а не открывает приложение сразу.**
В базе не записан адрес Mini App. Запустите деплой ещё раз; если адрес нестандартный — задайте
переменную `APP_URL`.

**Mini App показывает «Server error».**
Если вы оператор (шаг 10), бот пришлёт вам текст ошибки, а `/admin` покажет последние. Частая
причина — обновление изменило базу, а миграция не применена: посмотрите предупреждения в логе
деплоя.

**Деплой падает с `Too many modules per app`.**
Платформа принимает не больше 100 модулей в папке `tgcloud/`. Это касается только тех, кто
дорабатывает код: объедините мелкие модули.

## Как всё удалить

- **Свои данные из бота** — команда `/delete_me` в чате с ботом. Копии файлов в группе-архиве
  остаются: группа ваша, удалите её в Telegram.
- **Инстанс целиком** — удалите бота в @BotFather (`/deletebot`) и свою копию репозитория на
  GitHub (**Settings** → **Delete this repository**).

## Ответственность оператора

Собеседники не получают уведомления о том, что их удалённые и изменённые сообщения
сохраняются. Если вашим ботом пользуется кто-то кроме вас, их переписка хранится в базе вашего
бота — и отвечаете за неё вы. Законы о тайне переписки различаются по странам.
