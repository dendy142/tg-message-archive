# Возможности рантайма Telegram Serverless

Документация платформы не описывает часть возможностей, от которых зависят решения проекта.
Их проверяет самопроверка `npm run admin -- '{"selftest": true}'` после каждого деплоя и сохраняет в
`app_meta.capabilities`. Код читает результат через `capabilities()` из `lib/repo/state.js`, поэтому
корректно работает в обоих случаях.

| Возможность | Где используется | Если есть | Если нет |
|-------------|------------------|-----------|----------|
| FTS5 (`CREATE VIRTUAL TABLE … USING fts5`) | поиск | индекс `messages_fts`, `MATCH`, слова ищутся с начала | поиск `LIKE` по `search_text`, подстрокой |
| `crypto.subtle.digest` | PIN-код | PBKDF2 через WebCrypto | SHA-256 на чистом JS (`lib/util.js`) |
| `getUserProfilePhotos` для собеседника бизнес-чата | аватары | фото в профиле и списке чатов | инициалы |

`getUserProfilePhotos` проверяется на `app_meta.operator_id`. Без оператора проверка
пропускается, и аватары пробуются лениво: при открытии профиля и при входящем, не чаще раза в
сутки на чат. После пяти отказов подряд `app_meta.cap_profile_photos = false`, и бот больше не
спрашивает. Сбросить: `npm run admin -- '{"resetCapability": "cap_profile_photos"}'`.

## Как посмотреть результат

```bash
npm run admin -- '{"selftest": true}'
```

В выводе есть блок `capabilities` — результаты для вашего инстанса.

## Известные расхождения с локальной заменой sdk

- В `WHERE` платформа принимает только числа, `Date` даёт «unsupported value type». Сравнения по
  времени идут через `tsGte`/`tsLt` из `lib/repo/state.js`.
- В рантайме нет `btoa` и `Buffer`. Base64 считается в `lib/util.js`.
- Ключи проекции `db.select({ ключ: … })` платформа, судя по всему, подставляет псевдонимами без
  кавычек: ключ — ключевое слово SQL (`all`, `where`, `order`, `group`…) даёт `near "all": syntax
  error`, а Mini App видит «Server error». Drizzle псевдонимы экранирует, поэтому
  `sdk-shim/db.js` отвергает такие ключи сам — тесты ловят это до деплоя.
- Пакетная вставка `db.insert(t).values([…])` со строками разного набора колонок на платформе
  даёт безликий «Run error». Drizzle сам дописывает недостающие колонки значениями по умолчанию
  и пускает 32766 параметров; платформа, видимо, нет. Переносимо: у всех строк пачки одинаковые
  колонки, параметров (строки × колонки) не больше `MAX_SQL_VARS` = 999 (`lib/util.js`).
  `sdk-shim/db.js` требует того же.
- Сырые запросы `db.run/all/get` возвращают значения без преобразования типов.

## Лимит модулей

Платформа принимает не больше 100 модулей на бота (`.js` в `tgcloud/`): сверх этого `tgcloud push`
отклоняет выкладку с `Error: Too many modules per app` и не меняет ничего в облаке. Сам предел в
ответе сервера не указан: он найден опытом — выкладку со 102 модулями платформа отклонила.
Мелкие части собраны в общие модули по смыслу (`lib/runtime.js`, `lib/util.js`, `lib/i18n.js` …), сейчас их 50;
`tests/modules.test.ts` не пускает в `main` больше 100.
